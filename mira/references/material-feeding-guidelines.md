# Material Feeding Guidelines

Use this guide when the user provides external materials to improve the math-modeling contest paper agent. The goal is to extract reusable judgment rules, not to memorize or copy source text.

## Intake Folders

Recommended raw-material layout:

```text
materials/
├─ raw/
│  ├─ contest_papers/
│  ├─ research_papers/
│  ├─ model_notes/
│  ├─ textbooks_or_courses/
│  ├─ code_examples/
│  ├─ datasets/
│  └─ rules_and_templates/
└─ extracted/
   ├─ excellent-paper-patterns.md
   ├─ model-library.md
   ├─ figure-table-rules.md
   ├─ scoring-rubric.md
   ├─ code-patterns.md
   └─ source-index.md
```

Keep raw files unchanged. Write extracted knowledge separately.

## Source Types

| Source type | Can feed? | Extract into | Do not extract |
|---|---:|---|---|
| Excellent contest papers | Yes | Paper structure, abstract patterns, result-analysis patterns, figure/table usage, scoring signals | Verbatim paragraphs, private team-specific tricks without attribution |
| Research papers | Yes, selectively | Model assumptions, equations, algorithm routes, parameter interpretation, references, validation ideas | Research-paper writing style, literature-review bloat, unsupported contest claims |
| Non-contest Chinese academic papers | Yes, selectively | Chinese method explanation, domain variables, indicator sources, validation metrics, data-processing details, citation candidates | Academic-paper genre, literature-review structure, innovation-claim wording, long background sections |
| Model/method notes | Yes | Model cards, suitability rules, inputs/outputs, constraints, solver choices, common pitfalls | Bare lists of model names without decision rules |
| Textbooks/course notes | Yes | Definitions, derivation summaries, standard algorithms, model limitations | Long textbook exposition |
| Code examples | Yes | Reusable implementation patterns, data IO conventions, plotting patterns, numerical checks | Unreviewed copy-paste code, hardcoded results |
| Datasets | Yes | Schema, units, cleaning rules, missing-value handling, sample scripts | Fabricated values or altered raw data |
| Competition rules/templates | Yes | Formatting constraints, required sections, citation rules, page limits | Rules from unrelated contests as universal facts |
| Other agents' generated papers | Yes, cautiously | Candidate structure, figure/table, validation, and packaging patterns after calibration | Treating them as official excellent papers or copying their claims/references |

## Extraction Workflow

For each source:

0. Run the reusable extractor first when the file type is supported:

```powershell
python "$PROJECT_ROOT\.codex\skills\mira\scripts\extract_materials.py" `
  --recursive `
  --render-pdf `
  --output-dir "$PROJECT_ROOT\materials\extracted\material-extraction\<short-source-name>" `
  "<source-file-or-folder>"
```

Use the generated `extraction_manifest.json`, `texts/`, `rendered/`, and
`tables/` as the reading surface. Do not edit the raw source files.

1. Record metadata in `materials/extracted/source-index.md`: title, path, source type, year, topic, reliability, and useful sections.
2. Extract concise reusable patterns. Prefer bullets, tables, schemas, and checklists.
3. Label each extracted item as one of:
   - `writing_pattern`
   - `model_card`
   - `knowledge_card`
   - `figure_rule`
   - `code_pattern`
   - `scoring_rule`
   - `citation_candidate`
   - `data_schema`
4. State where the pattern applies and where it does not apply.
5. If the source is copyrighted, paraphrase. Do not copy long passages.
6. Promote only stable, generally useful rules from `materials/extracted/` into skill `references/`.

For an excellent contest paper selected for deep reading, save one source note
under `materials/extracted/paper-learning/`. Record source provenance and
quality signal, structure and argument map, modeling and solver pattern, each
figure/table's claim role, validation evidence, citation candidates and their
verification status, reusable patterns with `applies when` / `do not use when`
boundaries, and features that must not be imitated. Keep observations supported
by only one paper in that source note. Add a pattern to
`materials/extracted/excellent-paper-patterns.md` only after another independent
paper or official judging material confirms it; promote it into Mira references
only when it is also operational and scoped.

For algorithm-heavy materials, create a `knowledge_card` when the reusable value is "how to make the method work" rather than just "what the method is": neighborhoods, operators, recurrence details, parameter ranges, normalization, failure signs, repair moves, validation requirements, or paper-claim limits. Save candidate cards under `materials/extracted/knowledge-cards/` using `domain-knowledge-injection.md`.

If a source is generated by another agent, label it as `agent_output_sample`.
Do not promote its patterns unless they are confirmed by official judging
criteria, real excellent papers, or a reproducible Mira run.

For large local corpora such as `$PROJECT_ROOT\Math_Model`, first read `math-model-corpus-protocol.md` and generate `materials/extracted/math_model_corpus_index.md`. Then select a small number of relevant files by contest, model type, algorithm, or judging need. Do not summarize the whole corpus.

## Research Paper Boundary

Research papers are useful for methods, not for the final paper genre.

Allowed uses:
- Understand a model's assumptions and equations.
- Find validation methods and comparison baselines.
- Identify real citations when the contest paper needs background support.
- Learn how parameters are estimated or interpreted.
- For Chinese academic papers, learn domain vocabulary, model explanation, indicator definitions, data-processing choices, and validation metrics that can be converted into contest-paper sections.

Blocked uses:
- Converting the contest paper into a literature-review paper.
- Writing academic contribution claims.
- Importing complex methods that cannot be run, explained, or validated during a contest.
- Copying literature-review wording.
- Treating a journal/thesis structure as a mathematical modeling contest template.
- Using long "research status" sections, novelty claims, or dissertation-style background as Mira writing patterns.

## Learning Priority By Source

Mira is a Chinese mathematical modeling contest-paper agent. When sources differ, use this priority:

1. Chinese contest excellent papers: learn contest format, subquestion structure, abstract style, result placement, figure/table rhythm, and scoring signals.
2. MCM/ICM or other contest papers: learn model depth, problem decomposition, validation logic, and comparison style; translate only the reusable modeling pattern into Chinese contest form.
3. Chinese academic/research papers: learn methods, domain mechanisms, variable definitions, indicator sources, data preprocessing, validation metrics, and real citation candidates.
4. Textbooks/course notes: learn standard formulas, assumptions, algorithms, and pitfalls.
5. Other agents' generated papers: learn only candidate packaging ideas after calibration; never treat them as ground truth.

For non-contest academic papers, do not create `writing_pattern` entries unless the pattern is a contest-compatible explanation tactic such as "state variable meaning before formula" or "place residual table beside parameter estimate." Prefer `model_card`, `scoring_rule`, `figure_rule`, `citation_candidate`, and `data_schema`.

## Quality Rules

- One source should produce a small number of high-value rules, not a full summary.
- Extraction output is not learned knowledge by itself. Promote only after reading
  the extracted text, rendered pages, tables, or code and checking scope fit.
- Every extracted model must become a model card, not just a note.
- Every extracted expert algorithm tactic must become a knowledge card, not just a paragraph in a summary. A useful card names trigger pattern, when not to use it, operator/mechanism, parameter/scaling rule, validation, failure signs, repair move, and source confidence.
- Every extracted writing pattern must be phrased as a reusable structure, not copied prose.
- Every extracted figure pattern must include what claim the figure supports.
- Any citation candidate must be real and traceable to the source file or URL.
