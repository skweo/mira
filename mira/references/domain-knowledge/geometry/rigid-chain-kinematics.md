## Problem Patterns
- A contest object is made of many rigid links, vehicles, rods, or segments connected by fixed joint or hinge distances.
- The chain moves along a known curve or track and asks for positions, velocities, turn-in/turn-out timing, or feasibility.
- Adjacent points must stay at a fixed distance, so time-indexed coordinates cannot be generated by independent point motion.
- The curve is naturally parameterized by arc length, angle, or station coordinate.
- Chinese signals: 刚性链, 固定间距, 铰接杆件, 螺线, 曲线路径, 刚性连接, 碰撞风险.

## Applicability Conditions
- Segment lengths, handle spacing, and the leading point trajectory are known or can be parameterized.
- The chain is inextensible enough that fixed-distance constraints are the main geometry.
- A monotone route parameter exists for each link along the path, or route branches are explicitly handled.
- Required outputs can be computed from coordinates, headings, velocities, distances, or collision checks.

## Contraindications
- Do not model a rigid chain as a continuous rope unless the problem explicitly permits continuum approximation.
- Do not advance all nodes by the same time or angle increment when fixed Euclidean distances must be preserved.
- Do not treat a coarse time grid as final for collision, maximum speed, or critical pitch results.
- Do not ignore endpoint geometry: terminal links and body footprints may have different effective lengths.

## Algorithm Core
1. Define a route parameter, preferably arc length `s`, and coordinate map `r(s) = (x(s), y(s))`.
2. For the leading point, compute `s_0(t)` from the given speed or motion law.
3. For each following joint `i`, solve `||r(s_i) - r(s_{i-1})|| = d_i` with the correct branch/order constraint.
4. Compute headings from adjacent handles or the tangent, then derive rectangle/segment geometry for collision or display.
5. Derive velocities by differentiating the constraint equations or by refined numerical differentiation on a validated time grid.
6. Validate the chain by recomputing every adjacent distance, route ordering, and requested hard constraint.

## Operators / Mechanisms
| Name | Use | Feasibility note |
|---|---|---|
| arc-length map | Converts motion along a curve into coordinates | Must state whether `s` increases or decreases |
| distance root solve | Places each trailing point from the previous point | Use bracketed root finding or monotone search; audit residuals |
| branch/order constraint | Prevents selecting the wrong point on a spiral or turn path | Enforce route order and continuity from previous time |
| heading reconstruction | Builds rigid body orientation from two handles | Needed before rectangle collision or width offsets |
| constraint differentiation | Computes velocities without finite-difference noise | Cross-check against refined numerical differences |
| segment residual table | Audits fixed distances for all links | Max residual should be below the chosen tolerance |

## Parameter and Scaling Rules
| Parameter/objective term | Practical rule | Validation |
|---|---|---|
| Distance tolerance | Use a tolerance much smaller than reported length precision | Report max/mean distance residual |
| Time step | Coarse grid may locate candidates only | Refine near collisions, extrema, or threshold events |
| Route parameter bracket | Bracket each trailing point from previous solution and geometry | Check monotonic node ordering |
| Velocity derivative | Prefer analytic/implicit derivative when available | Compare with halved time step or local interpolation |
| Segment width/offset | Use the actual body width for collision | Audit rectangle vertices for representative nodes |

## Validation Requirements
- State contract: route equation, parameter convention, segment distances, body width, initial/terminal conditions.
- Fixed-distance audit for every adjacent pair and all reported critical times.
- Route-order and branch-continuity audit, especially on spirals or turn paths.
- Coordinate residual table for representative time points and the final reported table.
- Velocity validation: implicit derivative, refined finite difference, or step-halving comparison.
- If collision or extrema are involved, also retrieve `geometry/collision-sat` or `validation/continuous-extremum-search`.

## Failure Signs
- Node coordinates are generated by equal angle/time spacing instead of fixed Euclidean distances.
- The paper reports positions but no adjacent-distance residuals.
- A following node jumps to a different spiral branch between neighboring times.
- Speeds are computed from a coarse output table only.
- A critical pitch, time, or speed changes after halving the time step.
- Collision uses centerline distance only while the object has width.

## Repair Moves
- Rebuild the model around an arc-length or route-parameter representation.
- Use bracketed scalar solves for each trailing joint and carry the previous solution as the continuity prior.
- Add a distance residual CSV/table and fail the run if residuals exceed tolerance.
- Add local time refinement around any collision, threshold, maximum speed, or limiting pitch.
- Convert centerline segments into oriented rectangles and run SAT collision checks when width matters.

## Paper Usage
- Present the model as "curve parameterization + fixed-distance constraint propagation + residual audit".
- Do not call the trajectory exact; call it a numerical solution under stated tolerance.
- Put the fixed-distance residual and critical-event refinement evidence near the result table.
- Name this card in the modeling plan whenever positions or velocities are propagated through fixed-distance links on a curve.
