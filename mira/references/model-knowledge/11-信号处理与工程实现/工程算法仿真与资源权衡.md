# Model Card: 工程算法仿真与资源权衡

## Use When

- 题目要求设计可实现的算法，而不仅是数学公式。
- 存在性能指标和实现代价的冲突，例如误差/误码率/精度 vs 资源/功耗/时延/吞吐。
- 题目给出硬件、芯片、DSP、FPGA、ASIC、嵌入式、定点量化、并行度、缓存、查表、流水线等约束。
- 需要先搭建仿真平台，再用仿真结果进行参数扫描、拟合、优化或自动设计。

## Avoid When

- 题目只要求静态评价、纯预测、纯路径优化，且没有实现资源约束。
- 没有可运行仿真或可计算指标，无法验证性能。
- 方法复杂到无法在竞赛时间内实现、解释、验证。

## Typical Contest Tasks

- 工程算法设计、信号处理、控制系统、通信系统、嵌入式实现、工业仿真、性能-成本权衡、多目标工程优化。

## Required Inputs

| Input | Meaning | Unit | Required? | Notes |
|---|---|---|---:|---|
| System model | 物理/工程流程或信号链 | problem-specific | yes | 发射-信道-接收、传感-控制-执行等 |
| Performance metric | 性能指标 | dB/error/rate/etc. | yes | 如 BER、RSNR、RMSE、稳定时间 |
| Resource metric | 实现代价 | U/time/bit/power/etc. | yes if resource asked | 必须与题目给出的基本操作一致 |
| Design variables | 可调算法参数 | mixed | yes | 如 Pilot 开销、窗口长度、位宽、阈值、并行度 |
| Constraints | 性能、吞吐、资源、时序约束 | mixed | yes | 需区分硬约束和优化目标 |
| Simulation settings | 样本数、随机种子、参数网格 | none | yes for stochastic simulation | 保存到结果文件 |

## Outputs

| Output | Meaning | Paper use |
|---|---|---|
| Baseline performance table | 无补偿/基准算法/浮点算法表现 | 证明平台可信和改进有效 |
| Parameter scan table | 参数网格与性能结果 | 支撑关系分析和拟合 |
| Resource table | 各模块操作次数和资源量 | 支撑资源最小化 |
| Feasible design | 满足约束的参数组合 | 每问最终答案 |
| Tradeoff curve/table | 性能-资源关系 | 问题四或综合决策 |
| Code map | 仿真和求解脚本清单 | 可复现性 |

## Variables and Parameters

| Symbol | Type | Meaning | Unit | Source or estimation |
|---|---|---|---|---|
| `x` | state/signal | 系统输入、信号或状态序列 | problem-specific | 仿真生成或附件 |
| `theta` | state/noise | 隐状态、扰动或噪声过程 | problem-specific | 物理模型或估计 |
| `m` | design variable | 导频数、窗口长度、样本数等离散设计量 | count | 枚举/搜索 |
| `b` | design variable | 定点位宽或量化精度 | bit | 枚举/约束 |
| `P(b,m)` | metric | 性能代价 | problem-specific | 仿真或公式 |
| `R(b,m)` | metric | 资源代价 | U/time/power | 操作分解 |
| `J` | objective | 综合代价 | normalized | 权重或单位收益定义 |

## Core Formulation

常用建模链：

```text
1. 建立系统仿真平台：输入 -> 扰动/信道/对象 -> 算法 -> 输出 -> 指标
2. 验证基线：无算法、简单算法、浮点算法或题目给定基准
3. 参数扫描：对设计变量和场景变量生成性能表
4. 资源建模：把算法拆成题目指定的基本操作并计算资源
5. 单目标优化：在性能和吞吐约束下最小化资源，或在资源约束下最小化误差
6. 综合优化：归一化性能和资源，构造权衡函数或边际收益规则
```

典型优化形式：

```text
min R(b, m)
s.t. P(b, m) <= P_max
     throughput(b, m) >= throughput_min
     b in B, m in M
```

综合权衡可写成：

```text
min J(b, m) = alpha * normalized(P(b, m)) + beta * normalized(R(b, m))
```

或使用单位资源收益：

```text
gain(b) = performance_improvement(b) / resource_increase(b)
```

当 `gain(b)` 小于阈值时停止增加资源或切换方案。

## Solver or Implementation Route

- Preferred language: Python or MATLAB. MATLAB is common for signal processing examples; Python is preferred for reproducible data tables and plots when no toolbox is required.
- Recommended packages: `numpy`, `scipy`, `pandas`, `matplotlib`; MATLAB scripts should save `.mat`/`.csv` outputs.
- Baseline: simple/no-compensation, floating-point version, or official baseline.
- Search route: discrete variables such as bit width, Pilot count, window length, table size, and parallelism are suitable for enumeration/grid search.
- Resource route: compute operation counts before resource totals; keep add/multiply/lookup/buffer/delay separated.

## Validation

- Feasibility check: all hard constraints pass, especially throughput, delay alignment, resource bounds, and performance threshold.
- Sensitivity check: vary scenario variables and design variables; report feasible/infeasible regions.
- Baseline comparison: compare against no compensation/simple method/floating-point method.
- Error or uncertainty check: for Monte Carlo, report sample count, seed, repeated-run or statistical-error logic.
- Resource audit: recompute total resource from the module table and operation costs.

## Paper Writing Notes

- 中文竞赛论文中先写“模型准备/仿真平台”，再分问题建立与求解。
- 摘要按官方问题逐段写：约束、方法、指标、结果。
- 对离散设计变量使用“枚举/网格搜索”是可接受的，但必须说明搜索范围。
- 定点量化要先讲位宽范围、溢出风险、量化噪声，再讲资源。
- 自动优化方案要包含触发条件、调整方向、停止规则和不可行/边际收益过低时的替代方案。

## Common Pitfalls

- 直接优化资源，但没有证明性能指标达标。
- 只画仿真图，不保存背后的参数表和结果表。
- 把浮点算法结果当成定点实现结果。
- 资源总量没有从操作表逐项重算。
- 对离散变量使用连续优化后随意取整。
- 综合代价函数没有归一化或权重解释。
- 自动设计只有流程图，没有输入、输出、阈值和更新规则。
