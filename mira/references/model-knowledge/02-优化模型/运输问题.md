# Model Card: 运输问题

## Use When

- 题目涉及多个供给点向多个需求点分配货物、人员、名额、车辆、产能或资源。
- 已知或可构造单位运输成本、时间、距离、损耗、风险或惩罚矩阵。
- 每个供给点有供给上限或产量，每个需求点有需求量或最低服务量。

## Avoid When

- 只有一条路径选择，不存在多源多汇分配。
- 决策对象不能拆分，但模型没有加入整数或 0-1 约束。
- 成本不是可加的单位成本，也无法转化为边费用。
- 供需、成本矩阵或容量数据无法从题目或附件确定。

## Typical Contest Tasks

- 物流调运、物资分配、产销平衡、车辆/人员分派。
- 供应点到需求点的低成本服务方案。
- 运输问题作为网络流、选址、配送、生产计划的子模型。

## Required Inputs

| Input | Meaning | Unit | Required? | Notes |
|---|---|---|---:|---|
| Supply vector | 每个供给点可供量 | resource unit | yes | 产能、库存、人数、车辆等 |
| Demand vector | 每个需求点需求量 | resource unit | yes | 可为等式需求或最低服务量 |
| Cost matrix | 单位分配成本 | cost/resource | yes | 可由距离、时间、费用或惩罚构造 |
| Balance policy | 供需是否平衡 | none | yes | 不平衡时需要虚拟供给点或需求点 |
| Integrality need | 是否必须整数 | none | if relevant | 人数、车辆、件数等通常需要整数 |

## Outputs

| Output | Meaning | Paper use |
|---|---|---|
| Allocation matrix | 从供给点到需求点的分配量 | 主要方案表 |
| Total cost | 目标函数值 | 最优或当前最优结果 |
| Supply-demand audit | 行列和、剩余供需、容量检查 | 可行性验证 |
| Sensitivity table | 成本、供给、需求扰动影响 | 稳健性分析 |

## Variables and Parameters

| Symbol | Type | Meaning | Unit | Source or estimation |
|---|---|---|---|---|
| `x_ij` | variable | 供给点 `i` 分配给需求点 `j` 的数量 | resource | 求解 |
| `s_i` | parameter | 供给点 `i` 的可供量 | resource | 题目/附件/预测 |
| `d_j` | parameter | 需求点 `j` 的需求量 | resource | 题目/附件/预测 |
| `c_ij` | parameter | `i` 到 `j` 的单位成本 | cost/resource | 题目/距离/时间/估计 |

## Core Formulation

```text
minimize sum_i sum_j c_ij x_ij
subject to sum_j x_ij <= s_i       for each supply point i
           sum_i x_ij >= d_j       for each demand point j
           x_ij >= 0
           x_ij integer            if indivisible
```

若供需完全平衡，可把供给约束和需求约束写成等式。若供给大于需求，可加入虚拟需求点吸收剩余；若需求大于供给，可加入缺口变量并设置缺货惩罚或服务水平约束。

## Solver or Implementation Route

- Preferred language: Python (`scipy.optimize.linprog`, `pulp`, `ortools`) or MATLAB.
- Structured baseline: balanced transportation tableau, LP/MILP, or min-cost flow.
- Data preprocessing: construct cost matrix, check unit consistency, decide whether to add dummy supply/demand.
- Sensitivity: perturb supply, demand, or key cost coefficients; report binding supply/demand constraints.

## Validation

- Feasibility check: allocation matrix row sums satisfy supply, column sums satisfy demand.
- Objective check: recompute total cost from `x_ij` and `c_ij`.
- Integrality check: indivisible resources must not be fractional.
- Balance check: document dummy node or shortage penalty when supply and demand are unbalanced.
- Sensitivity check: key supply, demand, or cost changes.

## Paper Writing Notes

- 先解释供给、需求和成本矩阵的来源，再给模型。
- 运输问题本质是结构化优化，不要直接跳到遗传算法或模拟退火。
- 若需求来自预测，必须先验证预测结果，再把需求送入运输模型。
- 若有多个同等最优分配，可用下游便利性、距离、风险或公平性进一步筛选。

## Common Pitfalls

- 没有说明成本矩阵如何构造。
- 供需不平衡却直接套平衡运输模型。
- 把人数、车辆、件数做成小数方案。
- 只报告总成本，不给分配矩阵和行列审计。
- 对预测需求没有误差或安全余量，导致分配方案脆弱。
