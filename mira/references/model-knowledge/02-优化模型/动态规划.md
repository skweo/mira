# Model Card: 动态规划

## Use When

- 问题可分解为多个阶段，每个阶段的决策会影响下一阶段状态。
- 存在状态变量、转移关系、阶段收益或阶段成本。
- 目标具有最优子结构，例如总成本最小、总收益最大、路径/库存/资源分配最优。

## Avoid When

- 当前决策不影响未来状态，只是一次性静态优化。
- 状态空间过大且没有压缩、剪枝或近似策略。
- 阶段、状态、决策和转移无法清楚定义。
- 约束跨越多个阶段但没有被纳入状态或审计。

## Typical Contest Tasks

- 多阶段资源分配。
- 生产与存储、库存控制、设备更新。
- 分段路径或调度。
- 带状态转移的最优策略设计。

## Required Inputs

| Input | Meaning | Unit | Required? | Notes |
|---|---|---|---:|---|
| Stage set | 决策阶段 | stage index | yes | 时间、工序、节点、任务等 |
| State variables | 每阶段状态 | mixed | yes | 库存、剩余资源、当前位置、已完成集合等 |
| Decision set | 每阶段可选决策 | mixed | yes | 需受状态和约束限制 |
| Transition rule | 状态转移 | mixed | yes | `s_{t+1}=T(s_t,a_t)` |
| Stage cost/reward | 阶段成本或收益 | cost/reward | yes | 可加或满足递推 |
| Boundary condition | 初始/终止状态 | mixed | yes | 决定可行策略范围 |

## Outputs

| Output | Meaning | Paper use |
|---|---|---|
| Value table/function | 每个阶段和状态的最优值 | 解释递推结果 |
| Policy table | 每个状态下的最优决策 | 最终方案 |
| Reconstructed path/schedule | 从初始状态回溯的策略 | 结果表 |
| State audit | 状态转移和约束是否满足 | 可行性验证 |

## Variables and Parameters

| Symbol | Type | Meaning | Unit | Source or estimation |
|---|---|---|---|---|
| `t` | index | 阶段 | stage | 题目定义 |
| `s_t` | state | 第 `t` 阶段状态 | mixed | 模型定义 |
| `a_t` | decision | 第 `t` 阶段决策 | mixed | 求解 |
| `F_t(s)` | function | 阶段 `t` 状态 `s` 的最优值 | objective unit | 递推 |
| `g_t(s,a)` | function | 阶段成本或收益 | objective unit | 数据/模型 |
| `T_t(s,a)` | function | 状态转移函数 | mixed | 模型定义 |

## Core Formulation

最小化型递推通常写作：

```text
F_t(s) = min_a { g_t(s, a) + F_{t+1}(T_t(s, a)) }
subject to a in A_t(s)
           hard_constraints(s, a)
```

最大化型把 `min` 改为 `max`。最后从初始状态按记录的最优决策回溯得到完整策略。

## Solver or Implementation Route

- Preferred language: Python or MATLAB.
- Implementation: table recursion, memoized recursion, shortest-path reformulation, or mixed-integer model for comparison.
- State compression: remove无关变量，合并等价状态，设置可达状态筛选。
- Baseline: greedy strategy, static optimization, or MILP/exact solver when规模允许。
- Complexity: report stage count, state count, decision count, and pruning rule.

## Validation

- Recurrence check: state, decision, transition, boundary condition are all explicit.
- Feasibility check: reconstructed strategy satisfies every stage constraint.
- Objective check: recompute total cost/reward from the reconstructed policy.
- Baseline comparison: compare with greedy or simple static solution.
- Sensitivity check: key transition cost, capacity, demand, or stage parameter.

## Paper Writing Notes

- 先说明阶段、状态、决策、转移和边界，再写递推公式。
- 若只在一个子问题内精确，论文应写清“在该状态空间和约束下精确求解”。
- 状态空间大时，必须说明压缩、剪枝、近似或改用启发式的原因。
- 动态规划适合作为结构化基线；若再用启发式，应比较其结果和运行代价。

## Common Pitfalls

- 只有流程分段，没有真正状态转移，却称为动态规划。
- 遗漏边界条件，导致递推无法复现。
- 状态变量不包含关键约束，回溯出的策略不可行。
- 只给最优值，不给策略表或回溯结果。
- 状态空间爆炸但没有复杂度说明。
