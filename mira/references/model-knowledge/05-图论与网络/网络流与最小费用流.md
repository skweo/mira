# Model Card: 网络流与最小费用流

## Use When

- 题目涉及从源点到汇点运输、调度、分配、容量约束或路径流量。
- 边有容量、单位费用、时间或收益。
- 节点满足流量守恒，或有供应/需求。

## Avoid When

- 只是单条最短路径，不需要流量。
- 边权不是可加费用，且无法转化。
- 流量不可拆分但模型没有整数约束。
- 网络结构、容量或需求无法确定。

## Typical Contest Tasks

- 物流运输分配。
- 供需网络调度。
- 最大流/最小割。
- 最小费用最大流。
- 设施到客户的流量配置。

## Required Inputs

| Input | Meaning | Unit | Required? | Notes |
|---|---|---|---:|---|
| Node set | 节点集合 | node id | yes | 标明源点、汇点或供需点 |
| Edge set | 有向边 | pair | yes | 方向必须明确 |
| Capacity | 边容量 | flow unit | yes | 最大流量 |
| Cost | 单位流费用 | cost/flow | if min-cost | 时间、距离、费用或惩罚 |
| Supply/demand | 节点供给/需求 | flow unit | if transshipment | 流守恒右端项 |

## Outputs

| Output | Meaning | Paper use |
|---|---|---|
| Flow matrix/table | 每条边流量 | 主要结果 |
| Total flow | 最大流或完成量 | 任务答案 |
| Total cost | 最小费用 | 目标结果 |
| Constraint audit | 容量、守恒、供需检查 | 模型验证 |

## Variables and Parameters

| Symbol | Type | Meaning | Unit | Source or estimation |
|---|---|---|---|---|
| `x_ij` | variable | 边 `(i,j)` 上流量 | flow | 求解 |
| `u_ij` | parameter | 边容量 | flow | 题目/数据 |
| `c_ij` | parameter | 单位费用 | cost/flow | 题目/估计 |
| `b_i` | parameter | 节点供需 | flow | 题目/数据 |

## Core Formulation

```text
minimize sum_(i,j) c_ij x_ij
subject to sum_j x_ij - sum_j x_ji = b_i        for each node i
           0 <= x_ij <= u_ij
```

最大流可把费用去掉，最大化源点流出或汇点流入。

## Solver or Implementation Route

- Preferred language: Python (`networkx`, `scipy.optimize`, `pulp`) or MATLAB.
- Data preprocessing: edge direction, duplicated edges, missing capacities, unit conversion.
- Baseline: shortest path ignoring capacity, greedy allocation, or LP relaxation when appropriate.
- Complexity: large networks may require specialized min-cost flow solvers.

## Validation

- Feasibility check: every edge respects capacity.
- Conservation check: every intermediate node inflow equals outflow.
- Demand/supply check: source/sink and customer demand are satisfied.
- Cost check: recompute objective from final flow table.
- Sensitivity check: capacity or cost perturbation on critical edges.

## Paper Writing Notes

- 网络流图要服务于供需/容量解释；大网络可只画关键边，完整表保存为独立结果文件。
- 最终结果必须给边流量表，不能只给总费用。
- 若流量不可拆分，说明是否加入整数约束。

## Common Pitfalls

- 忽略边方向。
- 只满足总供需，不检查中间节点守恒。
- 把容量约束遗漏为普通最短路。
- 没有从流量表重新计算总费用。
